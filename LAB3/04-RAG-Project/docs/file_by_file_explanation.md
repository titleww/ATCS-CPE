## 🟢 ไฟล์ที่ไม่ได้แก้ไขเลย (12 ไฟล์) — เป็น Engine กลางของระบบ

ไฟล์เหล่านี้คือ **แกนกลาง (Core Engine)** ของระบบ RAG ที่ออกแบบมาให้ทำงานได้กับข้อมูลอะไรก็ได้ จึงไม่ต้องแก้ไขเมื่อเปลี่ยนโดเมน:

---

### 📄 `build_index.py` — ตัวสร้างดัชนี (Index Builder)
**หน้าที่:** สคริปต์สำหรับเตรียมข้อมูลและสร้างดัชนีค้นหา **รันครั้งเดียวเมื่อข้อมูลเปลี่ยน**

**ลำดับการทำงาน 5 ขั้นตอน:**
1. โหลดไฟล์ข้อมูล `.txt` ด้วย `load_qa_file()` → ได้ list ของ Q&A records
2. ตัดข้อความเป็น chunks ด้วย `build_chunks()` → ได้ 38 chunks
3. แปลง chunks เป็นเวกเตอร์ด้วย `EmbeddingModel().encode()` → ได้ 38 เวกเตอร์ × 384 มิติ
4. สร้างดัชนี FAISS → บันทึกเป็น `document.index`
5. สร้างดัชนี BM25 → บันทึกเป็น `bm25_index.pkl`

**ทำไมไม่ต้องแก้?** → มันอ่านชื่อไฟล์จาก `config.py` อยู่แล้ว พอเปลี่ยน config มันก็ไปอ่านไฟล์ใหม่เองอัตโนมัติ

---

### 📄 `src/document_loader.py` — ตัวโหลดข้อมูลดิบ
**หน้าที่:** อ่านไฟล์ `.txt` แล้วแปลงเป็นโครงสร้างข้อมูล

**วิธีการทำงาน:**
- อ่านไฟล์ทีละบรรทัด
- เจอ `[หมวด: ...]` → จำหมวดไว้
- เจอ `Q:` → จำคำถามไว้
- เจอ `A:` → สร้าง record = `{id, category, question, answer, line_no}`

**ทำไมไม่ต้องแก้?** → ไฟล์ข้อมูลใหม่ใช้ format เดียวกัน (`[หมวด:]`, `Q:`, `A:`) จึงโหลดได้โดยไม่ต้องแก้อะไร

---

### 📄 `src/text_splitter.py` — ตัวหั่นข้อความ (Chunker)
**หน้าที่:** ตัดข้อความยาวเป็นชิ้นเล็กๆ (chunks) เพื่อให้เวกเตอร์แม่นยำขึ้น

**วิธีการทำงาน:**
- รับข้อความ + ขนาด chunk (400 ตัวอักษร) + overlap (50 ตัวอักษร)
- ถ้าข้อความสั้นกว่า 400 → เก็บทั้งชิ้น ไม่ตัด
- ถ้ายาวกว่า → ตัดเป็นชิ้น โดยให้ชิ้นที่ติดกันเหลื่อมซ้อนกัน 50 ตัวอักษร กันข้อความขาดตอน
- ฟังก์ชัน `build_chunks()` จะรวมคำถาม + คำตอบเป็นข้อความเดียวก่อนตัด

**ทำไมไม่ต้องแก้?** → ใช้ขนาดตัวอักษรเป็นเกณฑ์ ไม่ขึ้นกับเนื้อหา

---

### 📄 `src/embedding_model.py` — ตัวแปลงข้อความเป็นเวกเตอร์
**หน้าที่:** ใช้โมเดล `paraphrase-multilingual-MiniLM-L12-v2` แปลงข้อความภาษาไทยให้เป็นตัวเลขเวกเตอร์ 384 มิติ

**วิธีการทำงาน:**
- `encode(texts)` → แปลง list ของข้อความเป็น numpy array ของเวกเตอร์ (ใช้ตอนสร้าง index)
- `encode_query(query)` → แปลงคำถาม 1 ประโยค เป็นเวกเตอร์ 1 ตัว (ใช้ตอนค้นหา)
- `normalize_embeddings=True` → ปรับความยาวเวกเตอร์ให้เท่ากับ 1 เพื่อให้ Inner Product = Cosine Similarity

**ทำไมไม่ต้องแก้?** → โมเดลรองรับภาษาไทยอยู่แล้ว ใช้ได้กับข้อความทุกหัวข้อ

---

### 📄 `src/vector_store.py` — ตัวจัดการฐานข้อมูลเวกเตอร์ FAISS
**หน้าที่:** สร้าง บันทึก โหลด และค้นหาในดัชนี FAISS

**วิธีการทำงาน:**
- `build(embeddings)` → สร้างดัชนีแบบ `IndexFlatIP` (Inner Product) จากเวกเตอร์ทั้งหมด
- `save(path)` / `load(path)` → บันทึก/โหลดดัชนีจากไฟล์
- `search(query_vector, top_k)` → ค้นหาเวกเตอร์ที่ใกล้เคียงที่สุด คืน `[(ตำแหน่ง, คะแนน), ...]`
- ตำแหน่งที่ FAISS คืนมาตรงกับ index ของ `chunk_store.json` เป๊ะ

**ทำไมไม่ต้องแก้?** → เป็นตัวจัดการเวกเตอร์ล้วนๆ ไม่เกี่ยวกับเนื้อหา

---

### 📄 `src/hybrid_retriever.py` — ตัวค้นหาแบบผสม (Hybrid Search)
**หน้าที่:** ค้นหาเอกสารด้วย 2 วิธีพร้อมกัน แล้วรวมผลด้วย RRF

**วิธีการทำงาน (ฟังก์ชัน `retrieve()`):**
1. รับคำถาม (อาจมีหลายแบบจาก Multi-Query)
2. **Dense Search** → แปลงคำถามเป็นเวกเตอร์ → ค้นใน FAISS → ได้อันดับตามความหมาย
3. **BM25 Search** → ตัดคำ (ไทยใช้ PyThaiNLP, อังกฤษ split ปกติ) → ค้นด้วยคำตรงตัว → ได้อันดับตามคีย์เวิร์ด
4. **RRF** → สูตร `Score = Σ 1/(60 + Rank)` → รวมอันดับจากทุกวิธี → เอกสารที่ถูกเจอจากหลายวิธีได้คะแนนสูงขึ้น
5. ถ้าเปิด Reranker → ส่ง 20 ชิ้นให้ Reranker กรอง → เหลือ 3 ชิ้น

**ทำไมไม่ต้องแก้?** → ทำงานกับเวกเตอร์และ tokens ไม่ขึ้นกับเนื้อหา

---

### 📄 `src/rerankers.py` — ตัวจัดอันดับใหม่ (Cross-Encoder Reranker)
**หน้าที่:** ใช้โมเดล `BAAI/bge-reranker-v2-m3` ประเมินความเกี่ยวข้องของ query-document pair อย่างละเอียด

**วิธีการทำงาน (ฟังก์ชัน `rerank()`):**
- รับ query + chunks 20 ชิ้น
- สร้างคู่ `(query, chunk_text)` ทุกคู่
- Cross-Encoder ให้คะแนนทีละคู่ (ช้าแต่แม่นยำกว่า Bi-Encoder)
- เรียงจากคะแนนสูงสุด → ตัดเหลือ top 3

**ทำไมไม่ต้องแก้?** → โมเดล multilingual รองรับภาษาไทย, ทำงานกับข้อความทุกหัวข้อ
> ⚠️ **หมายเหตุ:** ระบบของคุณตั้ง `USE_RERANK = False` ไว้ จึงไม่ได้ใช้ Reranker จริงในตอนนี้

---

### 📄 `src/query_transform.py` — ตัวปรับแต่งคำถาม
**หน้าที่:** ปรับปรุงคำถามของผู้ใช้ก่อนค้นหา เพื่อให้ค้นเจอมากขึ้น

**2 ระดับ:**
- **ระดับไม่ใช้ AI (`normalize_query()`):** ตัดคำลงท้าย (ครับ/ค่ะ) + แทนคำแสลง
- **ระดับใช้ AI (`transform()`):** มี 3 โหมด:
  - **Rewrite** → เขียนคำถามใหม่ให้ชัดเจน
  - **Multi-Query** → แตกเป็นคำถามหลายแบบ
  - **HyDE** → สร้างคำตอบสมมติเพื่อใช้เป็นตัวค้นหา

**ทำไมไม่ต้องแก้?** → ฟังก์ชัน `normalize_query()` มีตาราง `SLANG_MAP` อยู่ แต่เป็นคำแสลงเรื่องสุขภาพ (ไม่ถูกเรียกใช้ เพราะข้อมูลดาราศาสตร์ไม่มีคำแสลงเหล่านั้น ไม่เกิด error)
> ⚠️ **หมายเหตุ:** ระบบของคุณตั้ง `USE_QUERY_TRANSFORM = False` จึงใช้แค่ `normalize_query()` ไม่ได้เรียก LLM

---

### 📄 `src/memory.py` — ตัวจำบทสนทนา
**หน้าที่:** เก็บประวัติคำถาม-คำตอบล่าสุด เพื่อรองรับการถามต่อเนื่อง

**วิธีการทำงาน:**
- `add_user(text)` / `add_assistant(text)` → บันทึกข้อความ
- `get_context()` → คืนประวัติเป็นข้อความสำหรับใส่ใน prompt
- `is_followup(query)` → เช็กว่าเป็นคำถามต่อเนื่องหรือไม่ (สั้น + ขึ้นต้นด้วย "แล้ว", "มัน" ฯลฯ)
- `forget_old_messages()` → ตัดข้อความเก่าเมื่อเกิน 6 รอบ แต่จำหัวข้อแรกไว้

**ทำไมไม่ต้องแก้?** → ทำงานกับข้อความทุกหัวข้อ

---

### 📄 `src/rag_pipeline.py` — ตัวควบคุมกลาง (The Brain)
**หน้าที่:** **ไฟล์สำคัญที่สุด** — เชื่อมทุกส่วนเข้าด้วยกันเป็นลำดับ

**ลำดับการทำงานในฟังก์ชัน `ask(query)` :**
```
ขั้น 1: ดึงประวัติ → memory.get_context()
ขั้น 2: ปรับคำถาม → transformer.transform(query)
ขั้น 3: ค้นหา → retriever.retrieve(queries)
ขั้น 4: เขียนคำตอบ → generator.generate(query, chunks, history)
ขั้น 5: บันทึก → memory.add_user() + memory.add_assistant()
```

**ทำไมไม่ต้องแก้?** → มันเรียกใช้โมดูลอื่นทั้งหมด ไม่มีข้อความ hardcode เกี่ยวกับเนื้อหา

---

### 📄 `src/generator.py` — ตัวสร้างคำตอบ (LLM Caller)
**หน้าที่:** เรียก LLM ให้เขียนคำตอบจากเอกสารที่ค้นเจอ

**วิธีการทำงาน:**
- `generate(question, chunks, history)` → ประกอบ Prompt ด้วย `build_messages()` → ส่งให้ LLM → คืนคำตอบ
- ถ้า LLM เรียกไม่สำเร็จ → ใช้เนื้อหา chunk แรกตอบแทน (graceful fallback)
- รองรับ 3 providers: **Ollama** (local), **OpenAI**, **Gemini**
- มี `NoLLM` class สำรอง → ถ้าปิด `USE_LLM` จะคืนเนื้อหาดิบแทน

**ทำไมไม่ต้องแก้?** → มันอ่าน Prompt จาก `prompt_templates.py` พอแก้ prompt ก็เปลี่ยนพฤติกรรมได้เลย

---

### 📄 `src/retriever.py` — ตัวค้นหาพื้นฐาน (Dense Only)
**หน้าที่:** ค้นหาด้วย FAISS อย่างเดียว (baseline ก่อนมี Hybrid)

**ไม่ได้ถูกใช้งานจริง** ในระบบปัจจุบัน เพราะ `rag_pipeline.py` เรียก `HybridRetriever` แทน แต่เก็บไว้เพื่อเปรียบเทียบ

---

### 📄 `src/index_meta.py` — ตัวตรวจสอบความสดใหม่ของ Index
**หน้าที่:** ตรวจสอบว่า index ที่ใช้ตรงกับข้อมูลปัจจุบันหรือไม่

**วิธีการทำงาน:**
- `save()` → บันทึก metadata (ขนาดไฟล์, เวลาแก้ไข, ค่า config)
- `warn_if_stale()` → เปรียบเทียบ metadata กับสถานะปัจจุบัน ถ้าไม่ตรงจะแจ้งเตือน
- ป้องกันไม่ให้ระบบค้นจาก index เก่าหลังเปลี่ยนข้อมูลแล้วลืมรัน `build_index.py`

---

### 📄 `src/__init__.py` — ไฟล์เริ่มต้น package
**หน้าที่:** ทำให้โฟลเดอร์ `src/` เป็น Python package ที่ import ได้

### 📄 `evaluation/` (4 ไฟล์) — ชุดวัดผลระบบ

| ไฟล์ | หน้าที่ |
|:---|:---|
| `build_golden_set.py` | สร้างข้อสอบอัตโนมัติ (Golden Set) จาก chunk → ได้ 27 ข้อ |
| `eval_retrieval.py` | วัดคุณภาพการค้นหา (Hit@K, MRR, NDCG) ทั้ง dense, bm25, hybrid |
| `eval_generation.py` | วัดคุณภาพคำตอบของ LLM (ใช้ LLM Judge) |
| `metrics.py` | ฟังก์ชันคำนวณค่าทางสถิติ (Hit@K, MRR, NDCG) |

**ทำไมไม่ต้องแก้?** → อ่าน golden set จากไฟล์ JSON และเรียก pipeline โดยตรง ไม่มีเนื้อหา hardcode
